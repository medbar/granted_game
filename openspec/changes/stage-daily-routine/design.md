## Context

Сервер уже хранит phase apartment/office/city, позиции и processed. Менять его протокол не требуется.
См. proposal.md. Существующие незакоммиченные изменения новой кампании сохраняются.

## Goals / Non-Goals

Изменить представление и пользовательский маршрут пролога без смены правовых правил.
Нет новой карты города, модели, произвольных заставок или сброса сохранений пользователя.

## Decisions

- Отдельный Node2D-представитель рутины рисует одну комнату по существующей геометрии уровня.
  Координаты сервера проецируются в увеличенный интерьер; отдельная физическая симуляция не вводится.
- Контекстные взаимодействия у предметов/двери; на работе только одна экранная кнопка.
  Счётчик документов и переходы подтверждает реальная Campaign.
- Метро — локальное представление транзакции commute/home, минимум 2.8 секунды.
  Ответ хранится до конца сцены; тики при переходе не отправляются, старые отменяются.
  При ошибке исходное состояние сохраняется, а UI разблокируется с сообщением.
- После двух UI-нажатий work — короткое подтверждение и home. Прямые серверные команды
  для старых тестов остаются совместимыми; тест ожидания command учитывает показ поездки.
- Существующие сохранения не перезаписываются/сбрасываются; phase office открывается сразу на работе.
- Рисование средствами Godot соответствует текущему code-native art, внешние графические зависимости не нужны.

## Risks / Trade-offs

- Медленный ответ → метро продолжает показывать ожидание до таймаута HTTP; не обещать прибытие.
- Параллельный тик → отмена перед переходом, запрет ввода, проверка revision сохранена.
- Прямой API всё ещё допускает действие из любой точки своей комнаты; spatial affordance относится
  к интерфейсу игрока, не вводит новую серверную авторизацию.
- Два документа — сохранённая настройка темпа, не новое утверждение о сюжете или смысле работы.
