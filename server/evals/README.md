# Эвалы законов

Основной набор: `legal_cases.json` (schema 2, `legal-reality-v1`). Он описывает семь реализованных
законов прототипа, а не обещает реализацию всех предложений из Obsidian Vault. Основания:
канонические Bureaucracy of Reality / Precedents и принятые ADR-002 / ADR-003.

## Запуск

Из корня репозитория:

```powershell
server\.venv\Scripts\python.exe server\scripts\run_legal_evals.py --mode frozen
server\.venv\Scripts\python.exe server\scripts\run_legal_evals.py --mode live
server\.venv\Scripts\python.exe server\scripts\run_legal_evals.py --mode live --case personal_then_public
server\.venv\Scripts\python.exe server\scripts\run_legal_evals.py --list
```

Frozen: 32 сценария, настоящая Campaign с фиксированными решениями адвоката, без LLM.
Live: 21 сценарий с настоящим настроенным Lawyer; 11 frozen-only случаев явно исключаются.
Конфигурация модели берётся из `server/.env`. Сетевые ошибки не считаются правильным отказом.
Ошибка исполнения/сохранения записывается как FAIL с `decision_status=error`; остальные cases
продолжаются. Runner не повторяет сценарий автоматически ради зелёного результата.
Ожидаемые значения одни и те же в обоих режимах; live никогда не подменяется фикстурой.
Неизвестный/пустой выбор завершает команду ошибкой. Любой провал выбранного case даёт ненулевой код.

## Что проверяется

- Правовое основание и объяснение вместе с точным эффектом в авторитетном состоянии мира.
- Публичный аварийный выход против личного пропуска: отдельные проверки игрока, полиции и другой двери.
- Защита от урона, распознавание полицией, режим автомобиля, классификация/регистрация объектов.
- Освещение и ход времени, включая паузу/возобновление и фактическое перемещение.
- Создание, область действия, повторное использование и загрузка прецедентов; повтор запроса без дубля.
- Неверное основание/цель/диапазон, отсутствие контракта, неподдерживаемое требование, исправление после отказа.
- Недопустимые побочные изменения и отсутствие мутации при отказе.

`expected.state` и `expected.precedents` — независимый oracle: не вычислять их через production `LAWS`.
`allowed_changes` ограничивает diff, а `probes` вызывает реальные правила мира на копии состояния.
Произвольная мутация, слова адвоката или правильный статус сами по себе не дают PASS.
Положительный результат теста отказа означает «мир корректно отказал», а не «желание исполнилось».

## Артефакты

Каждый запуск сохраняет отдельный `server/runtime/evals/legal-<timestamp>-<mode>/`:

- `suite.json` и SHA-256 фиксируют точный набор;
- `summary.json`: режим, selected/excluded, PASS по законам/категориям и отдельные decision_outcomes;
- `<case>/scenario.json`, `result.json` и before/after каждого шага: expected/actual, diff, запрос,
  ответы модели, обратная связь между попытками, время исполнения;
- `<case>/runtime/`: изолированная сессия, не игровое сохранение пользователя.

Время в отчёте — полное время шага, не time-to-first-action. Подготовка модели записывается отдельно.
Графическое доказательство текущей кампании — `client/tests/bureaucracy_runner.gd` и
`client/test-artifacts/bureaucracy/`. Серверные probes не заменяют визуальную проверку.

Новый case сначала добавляется в JSON и тесты, наблюдается RED, затем меняется реализация.
Перед принятием просматриваются отдельные провалы, не только средний балл.

## Исторические наборы

Файлы environment/Monty/agent levels относятся к архивному джину и запускаются профилем
`legacy_genie`. `bureaucracy_cases.json` — прежние 12 smoke-эффектов кампании, не основной oracle.
Старые unit-тесты сохранены и входят в полный pytest.
